## 怎么测

启动本地工作台（`npm start`，打开 http://127.0.0.1:4310），在“任务工作台”“图纸重建”“订单评审”“零件检索”任一页面输入框下方的 **测试案例** 中点击案例卡片即运行。案例会附上图纸并提交给 AGH；过程中的每次工具调用和检查结果实时显示在上方对话记录中，完成后写入“历史记录”。未配置模型 API Key 时，点击案例会提示，并可直接打开模型设置。

案例清单：`assets/demo-cases/cases.json`。图纸为本项目原创的带文字层矢量 PDF（生成脚本 `tools/demo_cases/make_drawings.py`）；订单使用明确标注的合成演示台账。`cases.json` 中的 `reference` 只供人工核对，不进入模型输入。

装配案例的稳定性（每次运行都用脚本把实测的各零件底面 Z 与 `cases.json` 中的 `reference.stack` 比对，不依赖模型自报）：

- 图注标出各零件 Z 范围后共跑 6 次，5 次完全正确。
- 唯一一次失败：模型给垫片的爆炸位移大于已移开的法兰 B，垫片拆卸路径与其碰撞；连续 3 次修复都没找到原因。
- 之后在路径检查结果中加入可操作的修复提示（指明哪个实例与谁碰撞、应缩短哪段位移或调整顺序），再跑 3 次 3/3 正确，其中 1 次首轮碰撞后按提示一轮修复。

兼容性测试（不作为提交结果）：MiniMax-M3 默认开启思考，单次请求的 8192 输出额度全部用于思考、来不及调用工具，4 次均失败；关闭思考（请求附带 `thinking: {type: "disabled"}`，现对 MiniMax-M3 自动启用）后连跑 3 次，3/3 位置全部正确（思考 token 为 0，每次 4–5 次请求、6–11k 输出 token）。

导出的记录（`assets/evaluation/agh-runs/rec-coupling`）是最后一次 Agnes 运行。单件案例的旧记录保留在 `rec-plate`、`rec-flange`，在 `report.json` 中标记为 `retired`。

## 导出 AGH 执行记录

- **历史记录 → 导出全部执行记录**：下载 ZIP，每个任务一个目录。
- **任务结果 → 导出本次记录（ZIP）**：只导出当前任务；旁边的“AGH 原生轨迹”为单个 JSONL 文件。
- 接口：`GET /api/history/export`，`GET /api/history/<任务ID>/export`。

每个目录包含：

| 文件 | 内容 |
|---|---|
| `trace.agnes.jsonl` | AGH 官方导出器（agnes 格式）输出的原生执行记录：会话、模型请求头、计费与 token、工具调用/结果、校验信号、回合结束等全部事件 |
| `task.json` | 工作台任务记录：输入、可读事件、结果与用量 |
| `README.md` | 可读摘要：模型、AGH 会话、工具调用顺序、检查表、最终回答与文件清单 |
| `input/` | 本次输入的图纸 |
| `artifacts/` | 最终 STEP、GLB、特征计划、三视图 SVG 与检查清单 |

导出时去除 API Key、令牌字段与本机绝对路径；原生记录 SHA-256 写在 README 中便于核对。

## 为这些案例做的通用改进

均为工具与流程层面的改进，对任意图纸生效，不按案例编号走特殊分支：

- CAD 工具支持按图纸标注方式布孔（`grid` 中心距阵列、`polar` 分度圆、`edge_offsets` 距边尺寸），模型直接抄写图纸数字，不再自己换算坐标。
- 新增按实体实测的孔检查：`hole_count`、`hole_pitch`、`hole_pcd`、`hole_positions`。孔位读错会被检查发现，不会因为外形和体积正确而误判通过。
- 新增 `industrial_request_clarification` 工具：缺少关键尺寸时结构化暂停，状态为“等待补充资料”，不算失败。
- 几何结果附带 `nextStep` 引导（验证 → 投影 → 报告；失败则修复），保证 build/validate/project 三步闭环。
- 工具参数规范化：兼容部分模型把数组写成 `{"item": [...]}`、把数字写成字符串的序列化习惯。
- 重写重建提示词：更短、分步，附一个与案例不同的示例；零件检索在关键词不全命中时按相关度排序。
