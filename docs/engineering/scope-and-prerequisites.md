## 2. WorkBuddy 接入方式

来源：WorkBuddy 开放平台文档 [连接器](https://open.workbuddy.cn/docs/connector)、[技能](https://open.workbuddy.cn/docs/skill)、[专家](https://open.workbuddy.cn/docs/expert)。

已核实的公开规范：

- 连接器推荐 **MCP + Skill**；远程服务使用 HTTPS 的 `sse` 或 `streamableHttp`，本地进程可用 `stdio`；一个连接器只配置一个 MCP Server。
- 单次请求建议在 **30 秒内**响应；`mcp.json` 的 `timeout` 默认 30000 ms。
- 用户自填 Token 模式：`connector-meta.json` 设 `auth_mode: "token"`，提供 `token-schema.json`，在 `mcp.json` 中用 `${VAR}` 引用；需声明 `minWorkbuddyVersion` ≥ **4.23.0**，凭证只保存在用户本机。
- stdio 的 `runtime` 托管 Node 声明需 WorkBuddy ≥ 5.0.0；更低版本依赖用户系统环境。
- Skill 为 `SKILL.md`（YAML frontmatter + 正文），可附 `references/`、`scripts/`、`templates/`。专家为 `plugin.json` + `agents/*.md`，可声明技能。
- 连接器打包后提交 WorkBuddy 团队审核，通过后进入市场。

本项目选择：

1. 主路径：云端 EngineerAgent 服务暴露 **streamableHttp MCP**，用户自填 Token（在网页端生成），与网页共享同一任务主体。
2. 备选：本地 stdio 适配器，只做协议转发到云端 HTTP API，本机不安装 Python/CAD。
3. Skill 写明支持范围、证据复核、缺项必须询问、禁止猜测尺寸、失败处理。

仍需有 WorkBuddy 的成员实测（D1 探针，记录版本号与截图）：

- [ ] 目标设备上小硕 × WorkBuddy 的版本号，是否 ≥ 4.23.0。
- [ ] 能否不经市场审核，在本机添加自定义连接器或自定义 MCP（否则需走审核，计入关键路径）。
- [ ] 文件交接：用户在对话中给出的图纸能否交给远程 MCP（上传链接、Base64 或平台文件能力）。
- [ ] 工具结果是否会发送给云端模型（影响“数据路径”说明）。
